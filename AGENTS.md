- Weekly planning (top priorities, focus, review) lives in the `planejamento_semanal` table, one row per user and week, accessed via `usePlanejamentoSemanal`; localStorage is only read once to migrate old data — so plans follow the user across devices.
- WhatsApp reminders run server-side in the `whatsapp-agenda` edge function, triggered by pg_cron with a secret from `cron_segredos`; every send is reserved first in `whatsapp_envios` (unique per user/type/block/day), capped per day, logged in `whatsapp_log`, and never retried — so a repeating job can never send duplicates.
- Missed-block reasons live in `bloco_motivos` keyed by (user, referencia, data), where referencia uses the shared `ag:`/`av:`/`cp:<id>@<original date>` format from `src/lib/motivos.ts` — the same format whatsapp-agenda uses, so every block source maps to one key.
- A prioridade do dia vive em `prioridade_dia`, uma linha por usuário e dia (UNIQUE), apontando para a *referência do bloco* no formato `ag:`/`av:`/`cp:` — não para a tarefa; é isso que permite compromisso e ação avulsa serem a prioridade, e dia sem linha é estado normal, nunca pendência.
- `referenciaBloco` mora em `src/lib/hoje.ts` porque identifica o bloco: motivo de falta e prioridade do dia são dois usos dela, não dois formatos.
- O coach escreve a mensagem em quatro janelas (7:30, 11:30, 13:30, 18:30) cujo envio é sempre ANTERIOR ao fim da janela, para a mensagem chegar antes do bloco que ela cobra; um teste trava essa invariante.
- O modelo devolve CAMPOS (primeiro passo, versão mínima, frase), nunca o texto final: o código monta a mensagem, então o formato não escapa, campo vazio some em vez de derrubar o envio, e o texto que a usuária escreveu na tarefa ganha do gerado sem depender de obediência.
- Todo texto que guia o coach (tom, regras, perfil de vendas, mapa de crenças) mora em `coach_perfil`, no banco, nunca no código: ajustar é UPDATE, não deploy — e o repositório é público, então conteúdo pessoal nunca entra em migração nem em arquivo versionado.
- `coach_frases` guarda as frases *enviadas* e as dos últimos 7 dias voltam no pedido como lista do que não repetir; o "tipo" é o título normalizado, não o id, senão a regra falharia justamente nas rotinas diárias.
- `tarefa_agendamentos.remarcacoes` é incrementada por trigger, e só quando a data anda para frente: remarcar acontece por três caminhos na interface, e arrastar dentro do mesmo dia é reorganizar, não adiar.
